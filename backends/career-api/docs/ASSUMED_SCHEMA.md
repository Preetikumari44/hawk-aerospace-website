# Existing `drone_applications` table: what the backend assumes

No `.sql` schema file was supplied with the project, and the live database was not reachable from the build
environment, so the mapping below is **derived from the original `submit_interview.php`** (its INSERT and duplicate
check). Verify it against your database before first use:

```sql
SHOW CREATE TABLE drone_applications;
```

| Column          | Written by backend as                        | Notes |
|-----------------|----------------------------------------------|-------|
| `id`            | auto-increment, generated by MySQL           | assumed `AUTO_INCREMENT` primary key (the PHP INSERT omitted it and its duplicate check selected it) |
| `fullName`      | trimmed text                                  | |
| `email`         | trimmed, lower-cased                          | duplicate check is case-insensitive |
| `phoneCode`     | e.g. `+91`                                    | |
| `phone`         | digits only (7-15)                            | |
| `country`       | the country-select value posted by the form (e.g. `+91`) | the original form posts the dialling code under this name |
| `residency`, `hasLicense`, `hasExperience`, `ownDrone`, `willingTravel`, `visaInvestment` | `yes` / `no` | |
| `experienceInfo`, `ownDroneInfo` | text, max 1000 chars, `Not Provided` when empty | **verify the columns are TEXT or VARCHAR(>=1000)**; if they are VARCHAR(255) lower `@Size`/`@Column(length)` in `ApplicationRequest` / `DroneApplication` |
| `cvFile`, `licenseFile` | storage key such as `cv/<uuid>.pdf` (empty string when no file) | relative to `STORAGE_ROOT`; legacy rows hold `uploads/cv/...` PHP paths and are untouched |

Columns not listed (for example a `created_at` with a default) are not mapped and keep their database defaults.
`spring.jpa.hibernate.ddl-auto` is `none`, so the application never alters this table.

## What is NOT verified
* Column types/lengths and charset (see above).
* Whether `email` / `phone` already have unique indexes.
* That the id column is `AUTO_INCREMENT`.

## New table (additive)
`drone_application_notifications` (see `db/migrations/V1__notification_outbox.sql`) stores the email-retry state.
